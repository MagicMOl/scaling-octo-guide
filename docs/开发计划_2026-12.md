# 开发计划与排期（2026-12 起，12 周到内测）

**起点**：原型 v2.3（七屏、双语、两处真 AI、BFF、物流追踪、新封面）
**目标**：12 周后交付可对外内测的 1.0（iOS + Android 内测包）
**假设**：单人 + AI 辅助。若加一名前端，可压到 8 周。

---

## 总览

| 阶段 | 周次 | 日期 | 主题 | 关键交付 |
|---|---|---|---|---|
| P0 | W1 | 12/01–12/05 | 设计收口 | 原型 v2.3、作品集更新 |
| P1 | W2–W4 | 12/08–12/26 | 数据底座 | 账号、云端存储、多端同步、导出删除 |
| P2 | W3–W4（并行） | 12/15–12/26 | BFF 上线 | Workers 部署、鉴权、共享限流、成本上限 |
| P3 | W5–W7 | 12/29–01/16 | AI 能力扩展 | 组队匹配、选型报价、评测集 |
| P4 | W6–W8（并行） | 01/05–01/23 | 体验补齐 | 状态全覆盖、动效、手机边界、无障碍 |
| P5 | W9–W11 | 01/26–02/13 | 原生壳 | Expo 两条链路、内测包 |
| P6 | W11–W12 | 02/09–02/20 | 合规与发布 | 隐私政策、合规改造、上架材料 |

**两个里程碑**：
- **M1（W4 末）**：换设备能看到同一份底片，AI 走服务端，花费可控。
- **M2（W11 末）**：10 人内测，两条核心链路可用，崩溃率 < 1%。

## P1 · 数据底座（W2–W4）

**选型**：Supabase（Postgres + Auth + Storage），备选 Cloudflare D1 + R2。

| 任务 | 说明 | 工时 |
|---|---|---|
| 数据模型 | users / film_blocks / records / projects / orders | 2 天 |
| 账号 | 邮箱 magic link；匿名账号可升级，资产不丢 | 2 天 |
| 迁移 localStorage | 首次登录时合并本地数据，冲突按时间取新 | 2 天 |
| 离线缓存 | IndexedDB 缓存 + 后台同步 | 2 天 |
| 导出 / 删除 | JSON 导出、账号删除 24h 内清空 | 1 天 |
| 权限 | 行级安全（RLS），一条记录只属于一个人 | 1 天 |

**验收**：两台设备登录，底片一致；删除账号后 24h 内所有数据不可恢复。

## P2 · BFF 上线（W3–W4，与 P1 并行）

现有 `server/` 已支持 Node 与 Workers 双入口，本阶段是「上线 + 加锁」。

| 任务 | 说明 | 工时 |
|---|---|---|
| Workers 部署 | wrangler 部署，自定义域名 | 0.5 天 |
| 鉴权 | 校验登录态 token；匿名用户走轻量限额 | 1.5 天 |
| 共享限流 | Upstash Redis 计数器（代码已具备） | 0.5 天 |
| 成本熔断 | 日预算上限，超限返回友好降级 | 1 天 |
| 日志与告警 | 只记模型名与长度，异常推送到手机 | 1 天 |

**验收**：单日花费达上限自动停止并降级；并发 50 请求无 5xx。

## 关键路径与风险

| 风险 | 影响 | 对策 |
|---|---|---|
| P1 是唯一关键路径 | 晚一周全线顺延 | 账号与同步先做最小可用，导出删除后置 |
| 单人排期 | 任何病假都会挤压 P5 | P4 可裁剪，P0 已提前做完 |
| 数据导入没排进去 | 影响留存（用户懒得手填） | **建议在 P4 后插 2 周**：相册 / 日历导入 |
| AI 质量不可测 | 改了 prompt 不知道好坏 | 评测集必须先于 P3 扩展（已排在第一位） |
| 投资合规 | 法律风险 | 只做展示，不做资金流 |

---

## 需要你决定的三件事

1. **数据导入要不要提前**？提前就把 P5 推到 W11–W13，总周期变 13 周。
2. **BFF 走 Cloudflare 还是自己的服务器**？Cloudflare 便宜但国内访问不稳；自建每月约 ¥60 起。
3. **内测渠道**：TestFlight（iOS 需 $99/年开发者账号）还是先做 PWA（零成本，但功能受限）。
