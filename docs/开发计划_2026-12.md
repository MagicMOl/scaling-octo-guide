# 开发计划与排期（2026-12 起，12 周到公测）

**起点**：原型 v2.3
**目标**：12 周后交付 **PWA 版 1.0**（可安装到主屏、可离线、可分享链接），原生壳延后
**关键调整**（本版）：
1. **数据导入提前到 P3**（W4–W6），不再放最后——用户懒得手填十一年，导入决定留存。
2. **先做 PWA，不做原生**——省掉 App Store 与 TestFlight，分发改成链接 + 添加到主屏。

**假设**：单人 + AI 辅助。加一名前端可压到 9 周。

## P1 · 数据底座（W2–W4）

**选型**：Supabase（Postgres + Auth + Storage）。

| 任务 | 说明 | 周次 |
|---|---|---|
| 数据模型 | users / film_blocks / records / projects / orders | W2 |
| 账号 | 邮箱 magic link；匿名账号可升级且资产不丢 | W2 |
| 本地数据迁移 | 首次登录合并 localStorage，冲突按时间取新 | W3 |
| 离线缓存 | IndexedDB 先读后同步 | W3 |
| 导出 / 删除 | JSON 导出，账号删除 24h 内清空 | W4 |
| 行级安全 | RLS，一条记录只属于一个人 | W4 |

**验收**：两台设备登录 → 底片一致；删除账号 → 24h 内不可恢复。

## P3 · 数据导入（W4–W6）★ 提前

这是留存的分水岭：让底片在打开的第一分钟就有内容。

| 任务 | 说明 | 周次 |
|---|---|---|
| 相册导入 | 选照片 → 读 EXIF 拍摄时间 → 按年归入年份块 | W4–W5 |
| 日历导入 | 接日历事件（读书会、出差、发布会），提取年份与事件 | W5 |
| 简历导入 | 上传 PDF/图片 → 抽取公司与任职年份 | W5–W6 |
| 导入预览与确认 | 先给「将写入 2018 年 3 条」的预览，用户确认才落库 | W6 |
| 去重与冲突 | 同一年同一事件只留一条 | W6 |

**验收**：导入 200 张照片，5 秒内完成归年；用户可逐条撤销。

**注意**：相册读取必须在端上完成（EXIF 本地解析），照片**不上传**——这既是隐私要求，也省流量。

### iOS PWA 的两个硬限制（必须写进产品说明）

1. **存储可能被清理**：iOS 对 PWA 的 Storage 有配额，长期不用可能被清除 → **云端为准**，本地只做缓存。
2. **安装方式不直观**：必须在 Safari 里「分享 → 添加到主屏」，微信内置浏览器不支持。引导文案要写清楚。

## P7 · 商店化（条件触发，不排进这 12 周）

### 什么时候启动

满足任一条才启动，否则不做：

- 连续 4 周，**次周留存 ≥ 25%**（用过导入的人里）
- 有渠道方、合作方明确要求「必须有商店版本」
- 出现无法用链接解决的场景（如企业采购、学校合作）

**不满足就不上**。上商店换来的是一套长期合规义务，不是用户。

### 但这两件事现在就能并行办

它们最慢，且与开发无关，早办早好：

| 事项 | 周期 | 成本 | 说明 |
|---|---|---|---|
| 软件著作权登记 | 1–2 个月 | 300–1000 元 | 国内所有安卓商店强行要求，三选一：《计算机软件著作权登记证书》《APP 电子版权证书》《软件著作权认证证书》 |
| App 备案（工信部） | 约 20 个工作日 | 免费 | 强制，与是否联网无关；单机应用也要备 |

两者是独立流程，可同时办。

### 平台限制对照

| 平台 | 硬门槛 | 开发者成本 | 审核 |
|---|---|---|---|
| Apple App Store | **4.2 最低功能**：纯 WebView 套壳必拒 | $99/年 | 1–3 天，首次常被拒 |
| Google Play | 个人新号需 12 人测试 14 天；大陆无法上架 | $25 一次性 | 1–7 天 |
| 小米 / 华为 / OPPO / vivo / 应用宝 | 软著 + App 备案 + 实名 + 隐私合规 | 软著费用 | 1–7 天 |

### 上架前必须做的四项改造

| 改造 | 原因 | 工时 |
|---|---|---|
| **投资模块改成纯展示** | 募资类功能无牌照无法过审；去掉「认购」「打款」，只留估值与进度 | 2 天 |
| **加原生能力** | 破 4.2：至少两项，如离线数据库 + 相机导入 + 推送 | 5 天 |
| **AI 内容合规** | 免责声明、举报入口、有害内容过滤、结论标注「仅供参考」 | 2 天 |
| **隐私与删除** | 收集清单、单独同意、导出与删除入口要在产品内可见 | 2 天 |

### 商店化本身的时间线（触发后）

| 周 | 事项 |
|---|---|
| W1–W2 | 投资模块改造、原生能力补齐 |
| W3 | 隐私与 AI 合规材料、截图与描述 |
| W4–W5 | 提审、按驳回意见修改（预留两轮） |
| W6–W8 | 安卓各家商店逐个提审（每家要求略有差异） |
| W9–W12 | 灰度放量、看崩溃与差评 |

### 退出条件

- 若改造中评估「投资模块砍掉后产品价值明显下降」，**停在上架前**，继续 PWA
- 若两轮提审仍被拒（尤其 Apple 4.2），**不再投入**，PWA 已经能覆盖

## 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| iOS 存储被清理 | 用户以为数据丢了 | 云端为准 + 明确的「已同步」状态 |
| 相册权限被拒 | 导入走不通 | 保留手动补记与简历导入两条后备 |
| P1 是关键路径 | 晚一周全线顺延 | 先做最小可用（登录 + 同步），导出后置 |
| 春节（2/6 前后） | W11 效率下降 | 已在 W12 留一周缓冲 |
| 单人排期 | 病假即延期 | P5 的动效与无障碍可裁剪 |
| 软著 / 备案晚办 | 商店化被卡 2–3 个月 | 现在就并行启动，与开发无关 |

## 需要确认

1. **软著与 App 备案要不要现在就办**？这是 P7 唯一的长周期项，与是否上架无关——办了不用也不亏。
2. **投资模块的底线**：如果最终必须砍掉「认购」，产品叙事要改成什么？这是 P7 的最大变量。
3. **导入是否要支持微信/QQ 相册**？技术上走系统相册即可，但要说明「不用上传原图」。
2. **PWA 要不要上应用商店**（如国内的快应用或通过 WebView 套壳）？这一步会重新引入审核，建议先不发。
