## 二、真正的技术依赖（只有五处，绕不过）

| 依赖 | 为什么绕不过 | 处理 |
|---|---|---|
| 表结构 → 数据迁移 | 没有表，迁移无从写 | 韩东先出 schema，沈亦按 schema 写导入 |
| 接口契约 → 前端联调 | 字段没有，前端只能写假数据 | 契约先定，前端用 mock 并行 |
| 结论结构 → 评测集 | 结构没定，断言写不了 | 陆星野先出 JSON 结构 |
| token → 前端样式 | 没 token，各写各的颜色 | 叶知秋先出 tokens.css |
| 界面稳定 → PWA 缓存 | 页面还在变，缓存策略白做 | 岑野先做外壳缓存，页面级缓存后置 |

其余全部可以同时开工。

## 六、并行不等于无序：三个硬规则

1. **文件归属唯一**：每个文件只有一个负责人，改动走评审
2. **契约变更要广播**：改 schema、改接口字段，当天在群里同步，否则前端白做
3. **每天合并一次**：分支不过夜，避免最后一天大合并

违反这三条，11 个人并行的产出会少于 3 个人串行。
