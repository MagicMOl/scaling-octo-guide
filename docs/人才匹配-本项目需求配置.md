# 人才匹配 · 本项目需求配置

> 给左侧栏「人才匹配」面板用。填入后由插件自己算团队，可与 `docs/团队配置与人才需求.md` 第十节的结果对照。

---

## 一、面板里填什么

| 字段 | 值 |
|---|---|
| 项目名称 | 25号底片 · 个人经历档案与项目孵化 |
| 目标人数 | 5 |
| 每队上限 | 2 |

目标人数填 5 是推荐起步值。想看 7 人的结果，把它改成 7 再算一次。

## 二、技能要求（11 项）

技能名必须与人才库里的字段一致，否则匹配不上。

| # | 技能 | 门槛 | 权重 | 为什么需要 |
|---|---|---|---|---|
| 1 | 需求分析 | 4 | 3 | P0 设计收口、P6 合规表述 |
| 2 | 项目管理 | 3 | 2 | 跨阶段排期与验收 |
| 3 | React | 4 | 3 | 代表前端工程能力（现有实现为原生 JS，但工程素养同源） |
| 4 | 性能优化 | 3 | 2 | P5 的 PWA 离线与首屏 |
| 5 | Node.js | 3 | 3 | P1、P2 的 BFF 与鉴权 |
| 6 | 数据库设计 | 3 | 2 | P1 的档案模型与行级安全 |
| 7 | Python | 3 | 2 | P4 的评测集与提示词迭代 |
| 8 | 数据挖掘 | 3 | 2 | P4 的组队匹配与选型约束 |
| 9 | 视觉设计 | 4 | 2 | P0 封面与设计 token |
| 10 | 交互设计 | 4 | 2 | P4 动效与手机边界 |
| 11 | 用户测试 | 3 | 3 | P4、P5 的体验验收（人才库无 QA 角色，以此代偿） |

**约束**：门槛 1–5，权重 1–3（插件对权重上限是 3，不要填 4 以上）。

## 三、一键填入（推荐）

手动加 11 项要输 33 个值。在面板所在页面按 F12 打开控制台，粘贴下面这段，回车：

```js
(() => {
  const KEY = 'dsh-org-talent/v1';
  const state = JSON.parse(localStorage.getItem(KEY) || '{}');
  if (!Array.isArray(state.employees) || !state.employees.length) {
    console.warn('请先在面板里做任意一次操作（例如切个标签、改一次可用度），让它保存一次数据，再运行本段。');
    return;
  }
  state.plan = {
    name: '25号底片 · 个人经历档案与项目孵化',
    size: 5,
    maxPerTeam: 2,
    skills: [
      { name: '需求分析',   min: 4, weight: 3 },
      { name: '项目管理',   min: 3, weight: 2 },
      { name: 'React',      min: 4, weight: 3 },
      { name: '性能优化',   min: 3, weight: 2 },
      { name: 'Node.js',    min: 3, weight: 3 },
      { name: '数据库设计', min: 3, weight: 2 },
      { name: 'Python',     min: 3, weight: 2 },
      { name: '数据挖掘',   min: 3, weight: 2 },
      { name: '视觉设计',   min: 4, weight: 2 },
      { name: '交互设计',   min: 4, weight: 2 },
      { name: '用户测试',   min: 3, weight: 3 },
    ],
  };
  localStorage.setItem(KEY, JSON.stringify(state));
  console.log('已写入本项目需求，刷新页面生效');
  location.reload();
})();
```

**这段脚本只改 `plan` 字段**，员工、项目、需求池、备忘录都不动。

## 四、填完应该看到什么

| 目标人数 | 预期最佳团队 | 预期得分 |
|---|---|---|
| 5 | 林小满、顾飞、韩东、白露、贺婷 | 约 79（可用度按原值）|
| 7 | 上述 + 江屿、叶知秋 | 约 88（全员 100% 可用时）|

得分会随「可用度」数据变化。如果和本文档第十节对不上，多半是面板里的人员或可用度被改过，以面板为准。

---

## 五、看结果时注意三点

1. **互助分低是常态**：人才库里关键技能多数只有一个人达标，互助 0%–27% 属正常，这正是单点风险。
2. **设计组容易超员**：叶知秋、贺婷、唐然同组，同时进队会被「结构均衡」扣分。
3. **QA 与法务永远进不了队**：库里没有这两个角色，缺口只能外部解决。
