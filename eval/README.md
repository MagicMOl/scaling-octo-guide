# eval/ 评测集

改提示词之前先跑一次，改完再跑一次。没有这个，所有「感觉变好了」都是凭感觉。

## 文件

| 文件 | 用途 |
|---|---|
| `cases.json` | 30 条输入样本，虚构档案 |
| `run.mjs` | 跑分脚本，支持干跑与真实调用 |
| `fixtures/` | 干跑用的固定返回，验证断言逻辑 |
| `results.json` | 每次跑分的输出（`--out` 指定） |

## 30 条样本覆盖了什么

| 维度 | 覆盖 |
|---|---|
| 行业 | 文案、设计、后端、产品、运营、教师、医生、制造、餐饮、农业、销售、律师、建筑、护士、物流、主播、HR、摄影、自由职业、公务员、学生 |
| 年份跨度 | 1 年、2 年、3 年、4 年、5 年、10 年、11 年、15 年、**25 年** |
| 记录密度 | 每年 0 条、1 条、2–3 条 |
| 边界 | 空记录年（c11）、跨行三次（c12）、单年档案（c13）、超长一句话（c16）、中英混合（c17）、同行业十年（c18）、应届生（c14） |

## 怎么跑

**干跑**（不调用模型，只验证断言逻辑本身是对的）：

```bash
node eval/run.mjs --dry
```

期望输出：`1/3 通过`，并且 ok-c01 通过、bad-count 与 bad-year 被判失败。如果「断言逻辑有误」出现，说明检查器写错了。

**真实跑分**（需要 BFF 已启动）：

```bash
node eval/run.mjs --endpoint http://127.0.0.1:8787/api/analyze --out eval/results.json
```

可选参数：

| 参数 | 说明 |
|---|---|
| `--limit 5` | 只跑前 5 条，调试用 |
| `--timeout 25000` | 单条超时，默认 25 秒 |
| `--out path` | 结果写入文件，便于前后对比 |

## 判分规则

一条用例要**全部**通过才算通过：

| 规则 | 依据 | 说明 |
|---|---|---|
| 契约合规 | `contracts/validate.mjs` | 字段、长度、条数、价格 |
| 年份真实 | 证据里的 year 必须在该档案的年份集合中 | 防编造，这条抓得最准 |
| 时延 | 单条 ≤ 20 秒 | 超时算失败 |

输出包含总通过率、失败分布（按字段聚合）、逐条明细。

## 基线

**第一次真实跑分的结果存为 `eval/results.json`，并复制一份 `eval/baseline.json`。** 之后每次改提示词，对比两个文件的 `rate` 与 `rules`：

- `rate` 上升且 `rules` 里没有新出现的字段 → 改好了
- `rate` 持平但某个字段失败变多 → 换了个毛病，不是修好了
- `rate` 下降 → 回退

## 加用例

在 `tools/gen-eval-cases.mjs` 里加数组项，重新生成，而不是手改 `cases.json`——手改容易漏掉 `expectedYears` 字段。

新用例优先补这三类：

1. 真实用户给的档案（脱敏后）
2. 线上跑挂过的档案
3. 极端输入：只有一条记录、25 个年份、同一年两条矛盾记录

## 一个注意

`eval/cases.json` 里的档案是**虚构**的。真实用户档案不要进仓库，脱敏后放 `eval/private/` 并加进 `.gitignore`。
